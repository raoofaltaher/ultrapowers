# QA Lanes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use ultrapowers:subagent-driven-development (recommended) or ultrapowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close #4, #5, #6 and #10: suites that outlive the run, the `.failed` record and the missing troubleshooting text, the suppress-list parser, and the preflight's silent drops and false placeholders.

**Architecture:** `run-suite.sh` gains a process group, a pid file and a `--stop` mode, and the contract stops every live suite before the report. `judge.mjs` gets a stricter comment rule and accepts a pasted `NEW-FAILING ` prefix. `qa-preflight.mjs` warns on partly filled entries and limits placeholder detection to the three enum fields. No lane changes its outputs otherwise.

**Tech Stack:** bash (`setsid` where present, `kill -- -<pgid>` else the process-tree walk through `ps`/`taskkill` on Windows), node 18+ built-ins; `tests/qa-gatekeeper/test-run-suite.sh`, `judge.test.mjs`, `qa-preflight.test.mjs`.

**Spec:** `docs/ultrapowers/specs/2026-10-10-open-issues-fixes-design.md`, section 5.

## Global Constraints

- Zero dependencies (rule 1); LF endings for the shell script (rule 7); `scripts/lint-shell.sh --all` clean.
- `templates/qa/known-issues.md.tmpl` changes bump its entry in `templates/CHANGES.json` to `1.4.0`.
- The new `skills/qa-lane-6-suites/troubleshooting.md` and the STEP 8/9 change to `agents/qa-specialist.md` are prose that steers an agent: one pressure scenario each (rule 3), recorded in `tests/qa-gatekeeper/pressure/`.
- Each task's commit says `Closes #n`.

## Review Focus

1. A suite whose runner is a native Windows program (`dotnet test`) under Git Bash: `--stop` must end it too, not only the bash wrapper (test in Task 1).
2. `--stop` on a suite that already finished: exit 0 and no error, the out dir untouched (test in Task 1).
3. A suppress entry that ends with a real `#`-word but no trailing comment, such as `Cart adds item #2` alone on its line (test in Task 3).
4. A `qa.roles` entry whose `required` is the string `"true"` instead of a boolean: treated as not required, with a warning naming the field (test in Task 4).
5. A password that is exactly one of the enum spellings, `trx|vitest-json|junit-xml`: still accepted as a credential (test in Task 4).

### Task 1: `run-suite.sh` owns its process group and can stop it (#4)

**Files:**
- Modify: `skills/qa-lane-6-suites/scripts/run-suite.sh:55-80`
- Test: `tests/qa-gatekeeper/test-run-suite.sh`

**Interfaces:**
- Produces: `run-suite.sh <repo> <out dir> <command>` writes `<out>/pid` (the runner's process-group leader) beside `started-at`; a new mode `run-suite.sh --stop <out dir>` ends the group (`kill -TERM -- -<pgid>`, then `-KILL` after 5 s; on Windows `taskkill /T /F /PID`), writes `<out>/stopped-at` and exits 0, also when nothing is alive. A `QA_SUITE_TIMEOUT_SEC` environment variable, set by the contract from `suites[].timeoutSec`, makes the runner stop itself and write `stopped-at` with the reason `timeout`.

- [ ] **Step 1: Write the failing tests**

```bash
# a suite whose child sleeps 30 s then writes late.json; --stop after 1 s
bash run-suite.sh "$repo" "$out" 'sh -c "sleep 30; echo x > $QA_SUITE_OUT/late.json"' &
sleep 1; bash run-suite.sh --stop "$out"; sleep 2
[[ -f "$out/stopped-at" && ! -f "$out/late.json" ]] || fail "children survive --stop"
# a native node child
bash run-suite.sh "$repo" "$out2" 'node -e "setTimeout(()=>require(\"fs\").writeFileSync(process.env.QA_SUITE_OUT+\"/late.json\",\"x\"),30000)"' &
# ... same assertions
# --stop on a finished suite exits 0
# QA_SUITE_TIMEOUT_SEC=1 with a 30 s command writes stopped-at containing "timeout"
```

- [ ] **Step 2: Run and see them fail** — `bash tests/qa-gatekeeper/test-run-suite.sh`; expected: `late.json` appears, `--stop` is an unknown mode.
- [ ] **Step 3: Implement** — start the runner with `setsid` when available (else `set -m` and a subshell) so `$!` is a group leader; `trap` TERM to forward it; the timeout is a background watchdog that runs `--stop`.

- [ ] **Step 5: Commit** — `fix(qa-lane-6): run-suite owns its process group and stops it (part of #4)`.
