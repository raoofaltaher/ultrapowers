# GH-59 - Add web research and current-source validation to brainstorming, planning, and vulnerability hunting

## Context
Brainstorming, writing-plans and the vulnerability hunt reason mostly from the local code and the agent's prior knowledge, so they can miss changed library APIs, current framework guidance and newly disclosed vulnerabilities. This task adds a bounded research step to each: the agent first finds which web search, web fetch, scrape or documentation tools its harness and connected MCP servers give it (no tool is named or required), uses them for the technologies in scope, cites its sources, treats fetched content as untrusted data, and says so plainly when no such tool exists instead of inventing research. The hunt uses the same step to check current advisories and CVEs against the project's actual stack and versions.

## Definition of Ready
- [ ] The spec names where the step sits in each of the three skills and how it stays proportionate for tasks with no technology-specific context

## Definition of Done
- [ ] Brainstorming, writing-plans and the vulnerability hunt each detect the available research tools, use them when the task has technology-specific context, and record sources with links
- [ ] With no research tool available, each workflow states the limitation and fabricates nothing
- [ ] Hunt findings from advisories compare affected ranges with the project's versions and separate confirmed from unverified exposure
- [ ] The skill changes carry before/after pressure-test evidence through `ultrapowers:writing-skills`, and the offline suites pass
