# GH-35 - guardrail lane 4: an array slice such as a[1:n] is denied as psql interpolation

## Context
The lane 4 SQL rule of the guardrail analyzer (`analyzeSql` in `hooks/lib/qa-shell-writes.mjs`) refuses any `:name` sequence as psql variable interpolation, so a PostgreSQL array slice such as `select a[1:n] from t` is denied during a QA run although it is a plain read. This task lets a slice inside brackets pass while psql interpolation stays refused, in its three spellings (`:name`, `:'name'`, `:"name"`).

## Definition of Ready
- [ ] The rule's placement is agreed: inside `analyzeSql`, on the literal-stripped text

## Definition of Done
- [ ] `psql -U <ro role> -c "select a[1:n] from t"` and `select arr[2:3]` pass the analyzer
- [ ] `select :name`, `select :'name'`, `select :"name"` are refused, inside and outside brackets
- [ ] Unit tests in `tests/qa-gatekeeper/qa-shell-writes.test.mjs` cover the slice and the three spellings
